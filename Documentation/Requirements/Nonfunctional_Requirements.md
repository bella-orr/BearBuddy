# Nonfunctional Requirements

## Security and Privacy

- **NFR-1.1:** The system shall protect user information from unauthorized access.
- **NFR-1.2:** The system shall use secure communication protocols when transmitting data.
- **NFR-1.3:** The system shall minimize the collection of unnecessary personal information.
- **NFR-1.4:** The team shall use synthetic data during development and testing whenever possible.

## Accessibility

- **NFR-2.1:** The system shall provide clear and consistent navigation.
- **NFR-2.2:** The system shall use readable text and accessible color contrast.
- **NFR-2.3:** The system shall provide meaningful labels for interface elements.
- **NFR-2.4:** The system shall not rely only on color to communicate important information.

## Usability

- **NFR-3.1:** The system shall provide an intuitive interface for University of Cincinnati students.
- **NFR-3.2:** The system shall use consistent layouts, icons, and navigation.
- **NFR-3.3:** The system shall provide clear instructions and error messages.

## Performance and Reliability

- **NFR-4.1:** The system shall load primary screens within a reasonable amount of time.
- **NFR-4.2:** The system shall provide feedback while maps and external APIs are loading.
- **NFR-4.3:** The system shall handle errors and unavailable APIs without crashing whenever possible.
- **NFR-4.4:** The system shall maintain accurate and consistent schedule data.

## Maintainability

- **NFR-5.1:** The development team shall follow consistent coding standards.
- **NFR-5.2:** The system shall be organized into logical modules and components.
- **NFR-5.3:** The team shall use Git and GitHub for version control.
- **NFR-5.4:** The team shall document important code and system functionality.
